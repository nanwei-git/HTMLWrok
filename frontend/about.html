PROJECT OVERVIEW · SELF-INITIATED

让数据沿工作流
抵达答案

云栖数据工坊是一个面向数据分析与报表交付场景的工作流平台。 它把数据接入、处理步骤、分析报表与运行记录放在同一条链路上， 让一次分析从「临时操作」变成「可复用、可追踪的流程」。

POSITIONING

项目定位

不是静态报表页面，而是一套围绕分析任务组织的数据产品。

01 / WHY

从重复分析到流程复用

日常分析往往散落在 SQL、表格与聊天记录中，口径难以统一，结果难以追踪。 平台以工作流为核心对象，把抽取、清洗、转换、分析、可视化与交付编排为明确步骤， 每次运行都会留下耗时、处理量与成功状态。

02 / WHAT

数据、流程、报表的一体化视图

工作台聚合关键指标与最近动态；工作流中心呈现调度与执行情况； 报表中心承载最终分析成果；数据源页面统一展示接入状态。 四个模块由同一套 MySQL 数据模型与 RESTful API 支撑。

ANALYSIS PIPELINE

一条分析链路的五个阶段

工作流详情页中的步骤，正是按照这条链路组织与展示。

STEP 01

接入

连接交易库、行为接口、CRM 与文件数据，明确数据来源与同步状态。

STEP 02

清洗

剔除异常与重复记录，统一字段、时间与渠道口径。

STEP 03

分析

聚合指标、计算转化与分层，识别趋势和异常。

STEP 04

呈现

生成趋势图与摘要，将分析结论组织为可阅读的报表。

STEP 05

交付

按计划推送或人工发布，并记录每次运行的完整结果。

ARCHITECTURE

系统架构

原生前端 + Express MVC + MySQL，保持技术栈简单、结构清晰。

FRONTEND

原生页面与可视化

HTML、CSS 与 JavaScript 全部原生实现，不引用第三方库或 CDN。 页面共享同一套设计变量与组件样式；Canvas 提供低干扰的背景动画， SVG 用于报表趋势图，所有业务数据来自 `/api/` 接口。

BACKEND

RESTful MVC 服务

Node.js + Express 按路由、控制器、模型分层。所有接口以 `/api/` 为前缀， 使用统一响应格式 { code, msg, data }。跨域访问全部开放， 静态资源由 Express 直接托管，服务固定运行在 8509 端口。

DATABASE

五张核心业务表

`yan_data_sources` 保存数据源，`yan_workflows` 保存工作流， `yan_workflow_steps` 保存步骤，`yan_reports` 保存报表与趋势数据， `yan_workflow_runs` 保存运行记录。表名与字段统一使用 `yan_` 前缀。

DELIVERY

可追踪的交付结果

手动运行接口会写入新的运行记录，并重新计算成功率与最近运行时间。 报表详情页展示趋势数据、摘要、生成工作流与发布状态， 让分析结论能够回溯到具体流程与数据来源。
